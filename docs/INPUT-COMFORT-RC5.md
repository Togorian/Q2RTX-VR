# Input, comfort and save completion — source556

These source changes have focused CPU/syntax evidence. At source preparation on 12 November 2026, they had not been built into a release product or accepted in a headset. For a delivered candidate, the corresponding-source archive's `BUILD-RECORD.json` and the runtime folder's `RELEASE-MANIFEST.json` identify the actual build and package bytes. These records do not establish human headset acceptance or public-release approval. Existing source554 Makron movement escape and accepted source555 ownership/drop recovery remain selected.

Native input records each hand's action availability, neutral rearm, current pose validity and tracking confidence independently. The global sample/head freshness limit is still 100 ms. A current, finite, valid but incompletely tracked aim/grip pose may be used for up to 200 ms after that pose was fully tracked. Every use rechecks current sample age and grace. No cached pose is invented; inactive, invalid or non-finite pose data ends the grace until tracking returns. Each button/stick/grip action rearms after its own neutral sample, without releasing unrelated movement. A held trigger cannot become a new shot after action/aim loss and recovery.

Missing weapon-hand aim suppresses weapon/shot/selector/teleport publication while independently qualified head-relative locomotion and turning can continue. The final command consumer rechecks aim before attack. Menu navigation/confirm works from either available hand without requiring aim. Fixed hardware Menu remains separate from editable face shortcuts. Right Menu uses the existing short-release/350 ms hold distinction; Quest's reserved right Meta button is not exposed. Terminal quit can use the other eligible hand when either face action on the configured hand is unavailable; its existing neutral and 1.2-second chord rules remain.

Controller mode uses the existing OpenXR interaction-ready predicate, including FOCUSED, running/tracking and stop state. Desktop focus loss/minimisation does not force that controller mode into desktop throttling or interruption. Keyboard/mouse still requires desktop focus. Both modes render in VR, with accepted interruption/deliberate-resume and generation/serial boundaries preserved. Event overflow does not fabricate focus.

Current clean cvar defaults, menu reset values and the packaged configuration template agree on smooth turning at 360 degrees/second and teleport-only vignette. Snap turning and movement/turn vignette remain selectable. Ordinary startup retains saved choices; only an explicit Reset to Defaults restores the new values. The existing strength, radius, merge and 150 ms release curve remain. Published turn onset lasts up to 50 ms before the ordinary release tail; movement publication is limited to 100 ms. Invalid ownership/focus clears eligibility. These are source semantics, not a comfort finding.

The actual game view-offset producer omits only artificial fall-height dip and walking-bob height when VR is enabled. It retains viewheight/stance, kick origin and offset clipping, and the existing weapon-recoil observation. The unchanged client interpolation/predicted-origin path still adds stance offset and stair correction; the actual B2 eye transform then adds physical head displacement and recentring. Keyboard/mouse is not a flat-camera exception. No whole-viewoffset zeroing, movement physics change or recoil removal is used.

Manual save and autosave feedback is generated after their real writer/transaction result: a short success message, a longer failure message, or a retained-backup recovery message. An archived transition alone does not announce a published autosave. Game-writer ERR_DROP marks a pending save failed before ordinary menu recovery. The other game writers already check short writes and gzip close errors; their .current targets now receive the same Windows path/reparse precheck before opening. Published slots retain exclusive staging, backup and rollback. Failed rollback is distinguished from ordinary failure; no file format changes.

The selected Windows atomic writer already uses bounded unique exclusive creation with 16 attempts. Collisions and fixed stale .b2-new names are retained; a later save can use a new name. Unknown entries and prior backups are never swept. Directory publication is not power-loss atomic. No user save/config was read, migrated or overwritten by this work.

Historical checks (12 November 2026): these fixtures are not retained in this repository. Tests exercise actual native/reducer/caller spans with named OpenXR/engine effects; actual view-offset/eye math and vignette calculation; and actual save transaction/manual/autosave/notice functions with injected Win32 failures and synthetic files. They do not execute a game, driver, GPU or headset. Save serialisation itself is represented by labelled synthetic writers. Initial fixture compile/link and state-reset failures are preserved alongside corrected passing runs.

OpenXR semantics: [action activity](https://registry.khronos.org/OpenXR/specs/1.1/man/html/XrActionStateBoolean.html), [action synchronisation](https://registry.khronos.org/OpenXR/specs/1.1/man/html/xrSyncActions.html) and [space location flags](https://registry.khronos.org/OpenXR/specs/1.1/man/html/XrSpaceLocationFlags.html). The 200 ms grace is this product's explicit policy, not a guarantee supplied by OpenXR.
